# 步骤 08——仅用现有 U18 比赛进行整场留出的 Pass 改进比较

状态：进行中
开始日期：2026-11-12
前置：步骤 07 的固定零样本 Pass 基线、两类人工样本审查和 Drive 映射结论已记录

## 目标

在没有新视频的条件下，以现有两场 U18 比赛开展可复现、按**整场比赛**隔离的 Pass 改进实验。每轮用一场训练/开发，在另一场相同的两个半场比较冻结基线与改进模型；交换两场再重复。两场都已用于零样本诊断，因此结果必须称为“已检查数据上的整场留出比较”，不得声称有全新盲测比赛。

## 固定边界

- 比赛 A：`fc_tokyo_aomori_h1`、`fc_tokyo_aomori_h2`；比赛 B：`urawa_ryutsu_h1`、`urawa_ryutsu_h2`。
- 轮 A→B：仅用 A 的视频、Bepro 事件和人工复核结果训练/选择配置，在 B 的两半场测试。轮 B→A 对调。测试比赛的事件时间、错误样本、近远侧分布不得用于该轮训练、阈值选择、早停、数据清洗规则或超参数调整。
- 训练和测试均使用同一批现有 25 FPS masked 代理。原始带 Bepro 文字的视频不得直接输入模型。若未来获得干净原片，需另立基准。
- 先改进 `Pass`。Bepro `パス` 只是训练候选，已发现的时间偏移和疑似缺标不能自动当负例；训练用校正、排除及新增标签要另存版本并记录来源。`パス(受け手)` 不作为 `Drive` 训练标签。
- 原 7-fold/TTA 零样本模型与推理结果固定不变。比较时同一轮使用同一测试半场、GT 版本、遮罩、后处理和评价程序；若改进模型的 fold 数不同，另报告同容量基线。
- 两场先前均已被查看，任何依赖该轮测试错误而选择的改动都要显式披露；不得把这种分析称为独立测试。

### 已完成的低成本分数重排探索（尚非网络微调）

- `scripts/train_u18_pass_reranker.py` 使用既有 7-fold/TTA Pass 峰值、原始 Pass/Drive 分数和 Pass fold 分歧作为四个特征。训练监督只来自**训练比赛**的 Bepro Pass 与峰值在 ±1 秒下的一对一匹配；未把接球事件映射成 Drive GT，也未改原 BAS 权重或新增候选。
- 固定加权 logistic 回归与 L2 惩罚；每轮操作阈值只根据训练比赛上基线 `>=0.2` 的候选数量确定。测试比赛标签只用于最后评价。双向模型、原始分数哈希、每条测试峰值的原始/重排分数与比较指标保存在 `artifacts/u18_pass_cv/20261112_reranker_v3/`，`scripts/verify_u18_pass_cv.py` 可复算。
- A→B：测试 AP@1s 0.256→0.258；P 0.295→0.389；R 0.040→0.036；TP/FP/FN 31/74/746→28/44/749；far Recall 0.018→0.025。B→A：AP@1s 0.408→0.420；P 0.492→0.526；R 0.333→0.372；TP/FP/FN 291/301/583→325/293/549；far Recall 0.262→0.311。
- 结论仅为两个已检查比赛上的探索性迹象。浦和测试的 Recall 反而下降，不能把 AP 的微小升幅解释为已解决漏检。训练监督把未匹配峰值视为负例，而人工审查已发现视觉上有 Pass 的程序 FP 和时间偏移；后续网络微调前应先对训练比赛的目标标签做校准和补标。两场不提供独立的全新盲测证据。

## 验收

- 两个方向的训练文件和测试文件没有同一比赛；没有从留出比赛取训练标签或调参依据。
- 所有 GPU 运行经 Slurm；基线和改进模型的测试视频、GT、容差及评估器一致。
- 每个数值可以追溯到原始分数、权重、配置、输入哈希和测试日志。
- Drive 仅保留为预测输出和历史 receiver proxy 诊断，不以未核实接球标签评价或微调。
