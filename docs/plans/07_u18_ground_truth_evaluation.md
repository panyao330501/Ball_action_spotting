# 步骤 07——U18 Veo/Bepro Ground Truth 评估

状态：进行中
开始日期：2026-09-30
并行前置：步骤 06 的 IKOMA 人工审查仍可继续，但不作为本步骤正式指标输入

## 目标

使用两场 U18 比赛的四个 Veo 半场视频和 Bepro event XML，对既有 7-fold BAS 模型做零样本正式评估。先建立无标签泄漏、可复现的 GT/视频/预测契约，再报告 `Pass` 与暂定 `Drive` 的 AP、Recall、Precision、F1 和时间误差，最后产出可人工复核的 FP/FN 清单。

## 固定输入与决定

- 原始数据根目录：本地 `U18/`，整体被 Git 忽略。
- 只读取 8 份 `*_イベント.xml`；`*_チーム.xml` 和 `*_選手.xml` 是同一事件的重排，不重复计入。
- 动作时间使用 `MATCH TIME`；前半场直接作为视频秒，后半场减 `2700` 秒。XML 的 `start/end` 是约十秒审查窗口，不是动作时刻。
- `パス` 映射为 `Pass`，包括成功和失败。
- `パス(受け手)` 暂作为 `Drive` proxy，必须通过 50 条分层人工样本审查；结果未锁定前单独标注为 provisional。
- 原视频包含 Bepro 动作标签叠加。首选输入是无叠加的干净 Veo 视频；当前回退基准在缩放和 25 FPS 重采样前，用不透明黑框遮住左下角完整事件/球员标签区。
- 模型首尾各 `1.32` 秒作为上下文 guard，不进入正式分母；视频外事件不截断，直接排除并保留原因。

## 验收标准

- 原始视频/XML 不被修改或提交 Git；每个正式产物可追溯到输入 SHA-256。
- GT 转换数量、时间偏移和边界排除由自动化测试及正式运行清单证明。
- 输入视频不含可被模型读取的动作类别文字；masked 基准明确标注其视野损失。
- GPU 工作全部经 Slurm；四个半场均有原始分数、事件、清单和日志。
- 指标实现、容差、阈值、匹配规则和 `Drive` 暂定映射全部显式披露。
