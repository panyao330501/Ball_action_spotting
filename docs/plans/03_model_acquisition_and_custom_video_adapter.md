- [x] 记录下载 URL、发布日期/版本、文件大小、SHA-256、许可证和获取日期；训练产物由用户手动放入远端项目根目录的 `action/` 与 `ball_action/`，均受 Git 忽略规则保护。

验收：可追溯且已哈希的权重能被 `argus.load_model` 成功载入，不含缺失键、NaN 或不匹配参数。

- [x] 读取 `configs/poc_video.yaml`，验证源/代理身份和输入为 25 FPS。
- [x] 复用上游的 `MultiDimStackerPredictor`、`pad_normalize`、33 帧、步长 2 和原始后处理参数；使用 OpenCV 解码适配器，GPU 仅用于模型计算。
- [x] 以连续帧解码覆盖指定时间范围，正确处理 64 帧上下文边界并记录有效预测帧范围。
- [x] 导出不可变的各 fold 分数、fold 平均分数、帧号、`frame_index / 25.0` 秒和运行清单；不得在本步骤先丢弃低分。

验收：入口无需 SoccerNet 的比赛目录结构；可从配置运行；输出符合 `docs/data/label_and_artifact_contract.md`。

### 3. 60～90 秒端到端冒烟

## 风险和处理

- 权重链接失效或需要权限：停止在权重获取，记录可复现的阻塞信息，不以随机权重代替。
- 上游 `argus` 序列化和当前 Python/PyTorch 不兼容：优先在隔离 Conda 环境中作最小兼容修补，并记录变更；不升级核心依赖后继续假定权重可用。
- OpenCV 解码吞吐不足：先完成正确性测试，再评估 NVIDIA VPF；不能为了提速改变 25 FPS 时间契约。
- 低清晰度与画外动作影响的是模型效果，不是本步骤的输入完整性错误；在后续主观审查中标注可见性。
