# 总体实施计划

状态：基线计划  
建立日期：2026-08-31  
变更规则：只有项目范围、架构、阶段顺序、交付物或验收标准发生实质变化时才修改。执行进度写入步骤计划和 `docs/milestone.md`。

## 1. 目标

针对 `vs_飛鳥FC_20260704_trimmed_0930.mp4` 中首次开球后约 10 分钟的视频执行 `Pass` 和 `Drive` 动作定位，生成可供审查的叠加视频并分析无 GT 失败模式；随后使用 U18 Veo 视频和 Bepro event data 建立防标签泄漏的零样本正式评估。

本次 PoC 需要回答：

- 预训练模型能否在目标视频中给出可信的 Pass 和 Drive 时间戳？
- 预测的时间对齐是否足以支持人工审查？
- 哪些失败来自模型，哪些来自画面没有提供可见证据？
- 是否值得申请正式 GT 标注并进行模型适配？

## 2. 约束和假设

- 视频清晰度低于典型高质量转播视频。
- 摄像机可能跟随滞后或保持不动，导致动作发生在画面外。
- 视频全程使用单一摄像机，没有镜头切换。
- 模型推理在 `chiron` 上执行，可视化和主观质检在本地执行。
- 环境使用 Conda 管理。
- GitHub 只同步代码、配置和文档。
- 初始模型路线固定为预训练的 2023 SoccerNet Ball Action Spotting 冠军方案；其源码、权重和运行配置需在步骤 03 固定。
- `Drive` 保留为标准模型标签，不得未经说明改写为所有接球事件。

## 3. 系统数据流

```text
本地源视频
  -> 元数据和开球时刻检查
  -> 校验和一致的视频传输到 chiron
  -> 远端解码和 GPU 推理
  -> Pass/Drive 原始稠密分数
  -> 时序峰值提取和事件导出
  -> 校验和一致的结果传回本地
  -> 本地叠加渲染和集锦生成
  -> 低阈值分数与 fold 分歧生成漏检候选
  -> 可选 tracking 候选融合
  -> 主观审查和失败分析
  -> 决定是否申请 GT 或进行微调
```

原始稠密分数是远端推理和本地可视化之间的交接边界。调整阈值时不得要求重新执行 GPU 推理。

## 4. 实施阶段

### 步骤 01：项目、仓库和环境准备

目的：建立 GitHub 同步、Conda 环境、SSH 流程、目录布局、忽略规则和大文件传输规范。

主要产物：连接 GitHub 的本地仓库、远端检出、本地 `ballspot-viz`、远端 `ballspot-infer`，以及通过校验和验证的视频传输流程。

退出标准：本地可推送并在 `chiron` 拉取；本地 FFmpeg/OpenCV 检查通过；远端 PyTorch 能识别 RTX A6000；两端视频 SHA-256 一致。

### 步骤 02：视频检查和推理契约

目的：确定准确处理区间并规范时间基准，同时保持源视频不变。

工作内容：记录编码、时长、分辨率、帧率、音频和时间戳；确认用户已裁剪的视频在 `0.000` 秒即为开球；处理完整 `[0.000, 566.500]` 秒，绝不再次剪辑；检查普通比赛、远距离足球、摄像滞后、画面边缘和画外场景；按模型契约生成全时长固定帧率推理代理视频。

产物：`video_metadata.json`、推理区间配置、画面检查记录。退出标准是时间转换无歧义且往返误差不超过一帧。

### 步骤 03：模型获取和自定义视频适配

目的：复现预训练 Pass/Drive 模型，并支持任意 MP4 输入。

工作内容：固定上游源码、许可证、配置和权重；复现上游样例；实现自定义视频加载；保存逐时间步分数；配置区间、设备、批量大小、输出和随机种子。

产物：模型来源记录、远端推理入口、原始分数结构和 60～90 秒冒烟预测。退出标准是重复推理可复现、无 NaN/Inf 且时间对齐。

### 步骤 04：完整远端推理和时序后处理

目的：只生成一次稠密分数，并据此产生稳定候选事件。

工作内容：默认使用一张 GPU 完整推理；保存模型、配置、权重哈希和运行信息；按类别执行阈值、峰值提取和重复抑制；导出高、中、低置信度候选并保留原始分数。

产物：稠密分数、事件 JSON/CSV、推理清单和日志。退出标准是结构合规、时间有序、无意外重复且可复现。

### 步骤 05：本地可视化流程

目的：将预测渲染成适合主观审查的视频。

工作内容：叠加源时间码、标签、置信度和事件标记；Pass 为绿色、Drive 为橙色、可见性警告为灰色；标签从事件前约 0.5 秒显示到后 1.5～2 秒；保留音频；生成完整视频和事件集锦；未加入空间模型时禁止画框。

产物：`annotated_full.mp4`、`event_highlights.mp4`、渲染清单和日志。退出标准是时间基准、时长和音频同步通过，所有事件均出现在正确时刻。

### 步骤 06：可见性检查和主观审查

目的：区分模型行为和输入画面缺少证据造成的问题。

工作内容：标记 `VISIBLE`、`PARTIAL`、`OFFSCREEN`；审查每个预测；连续观看并记录明显可见漏检；从保留的稠密分数中联合低阈值峰值与 fold 分歧生成排序候选，可选融合标准化 tracking 候选；分类为正确、标签错误、时间误差、重复、误检、可见漏检、画外不可观测或歧义；保存代表性成功和失败片段。

产物：`review_notes.csv`、漏检候选 CSV/JSON、漏检候选审查集锦、置信度/事件时间轴和 PoC 报告。退出标准是全部预测和新增候选得到审查，重要漏检和画外区间被记录，主观统计与种子覆盖率不冒充正式 GT 指标。

### 步骤 07：U18 Veo/Bepro GT 评估

目的：利用教授提供的两场 U18 比赛、四个 Veo 半场视频和 Bepro event data，对固定 BAS 模型进行可复现的有 GT 零样本验证。

工作内容：固定视频/XML 哈希；以 `MATCH TIME` 建立半场相对 GT；直接映射 `パス`→`Pass`，审查后再决定是否接受 `パス(受け手)`→`Drive` proxy；遮住原视频自带的 Bepro 动作标签或改用干净 Veo 原片；在 `chiron` 通过 Slurm 运行相同 7-fold/TTA 模型；报告 `±0.5/1/2s` AP、mAP、Precision、Recall、F1 和时间误差；输出可人工复核的 FP/FN。第一轮不调参，若后续调参则按比赛交叉划分 dev/test。

产物：U18 GT JSON/CSV 和清单、Drive 语义审查表、四个 25 FPS 防泄漏代理及配置、四个半场原始分数与预测事件、正式指标 JSON 和错例 CSV。退出标准是输入无动作标签泄漏、四个半场推理可追溯、Drive 映射状态显式、正式指标和错例均可复现。

## 5. 测试门槛

- 门槛 A——基础设施：Git、Conda、SSH、GPU 和校验和通过。
- 门槛 B——适配器冒烟：60～90 秒推理可复现且时间对齐。
- 门槛 C——产物集成：远端预测无需手工修复即可本地渲染。
- 门槛 D——视频技术质检：时长、帧率、音频同步、叠加覆盖和事件数量通过。
- 门槛 E——主观审查：完成预测和可见漏检检查，并总结失败模式。
- 门槛 F——U18 GT 评估：GT 数量/时间转换、防标签泄漏、四半场推理和一对一时间匹配指标全部通过。

详细测试见 `docs/testing/test_strategy.md`。

## 7. 主要风险

- SoccerNet 转播视频与当前低清晰度单机位视频存在领域差异。
- 画面外动作无法恢复。
- `Drive` 与 `Reception(Drive)` 存在定义歧义。
- 旧模型依赖不兼容或权重失效。
- 视频为可变帧率或时间戳异常。
- 只针对一段短视频调整阈值可能过拟合。
- 原始 U18 视频自带 Bepro 动作文字，若不遮挡会造成严重 GT 泄漏；遮罩又会损失部分近侧画面。
- `パス(受け手)` 只是在语义上接近模型 `Drive`，未经人工审查不能视为完全等价。

通过可见性状态、保留原始分数、固定环境、短片冒烟、校验和验证和明确标签契约降低上述风险。
