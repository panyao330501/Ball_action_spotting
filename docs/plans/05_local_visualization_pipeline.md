# 步骤 05——本地可视化流程

状态：进行中
开始日期：2026-09-01
前置步骤：`04_full_remote_inference_and_postprocessing` 已完成
后续步骤：`06_visibility_and_subjective_review`

## 目标

在本地原始带音频视频上显示 58 个 Pass / Drive 候选的时间、标签与置信度，生成完整审查视频和按事件分组的集锦。该步骤只提供时间事件叠加，不绘制不存在的空间检测框。

## 固定输入

- 原始视频：`vs_飛鳥FC_20260704_trimmed_0930.mp4`，1280×720、30 FPS、AAC 音轨。
- 事件：`artifacts/inference/full_6835526/events.json`；默认候选为 Pass 34、Drive 24。
- 时间基准：事件 `time_sec` 直接对应原始视频的秒数，开球偏移为 0。

## 工作包

### 1. 叠加渲染器

- [ ] 实现本地渲染入口，读取事件 JSON，验证事件契约和源视频时间轴。
- [ ] 显示源时间码、当前/近期事件、标签和置信度；Pass 使用绿色，Drive 使用橙色。
- [ ] 每个事件从前 0.5 秒显示到后 2.0 秒；同窗多事件按时间排列。
- [ ] 保留原始音轨；不改变视频时长、尺寸或帧率；禁止绘制边界框。

验收：叠加视频可打开、音视频时长同步，任意事件通过源时间可复查。

### 2. 完整视频与事件集锦

- [ ] 生成完整 `annotated_full.mp4`。
- [ ] 为每个候选截取前 3 秒、后 4 秒的上下文，生成带事件标题的 `event_highlights.mp4`；片段不能越过源视频边界。
- [ ] 记录渲染参数、源/事件哈希和输出视频 FFprobe 信息。

验收：两份视频均存在、可解码，音频在完整视频中保留，集锦事件数与输入候选一致。

### 3. 本地技术质检

- [ ] 对完整视频检查时长、尺寸、帧率、音轨和可解码性。
- [ ] 从至少 3 个不同时间段抽帧，人工确认时间码和颜色标签位置正确。
- [ ] 检查集锦片段数量、顺序、边界截断和事件标题。

验收：所有交付视频均可供无 GT 的主观审查，问题进入步骤 06 的审查备注而不是静默修正事件。
