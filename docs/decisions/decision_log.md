## D-001——分离推理和可视化计算

- 日期：2026-08-31
- 状态：已接受
- 决策：GPU 模型推理在 `chiron` 执行；可视化渲染和审查在本地执行。
- 理由：远端拥有 8 张 RTX A6000，本地是目标审查环境。
- 影响：原始稠密分数和运行清单构成远端到本地的交接契约。

## D-008——按冠军方案生成全时长 25 FPS 推理代理视频

- 日期：2026-08-31
- 状态：已接受
- 决策：保留原始 30 FPS MP4 作为规范源；远端为模型生成无音频、全时长、25 FPS CFR 的代理视频。代理维持 1280×720，不缩放；上游模型的原生 `pad_normalize` 处理器将其居中补黑为 1280×736 灰度帧。
- 理由：上游预测脚本显式断言输入为 25 FPS，模型以 15 帧、步长 2 的 12.5 FPS 有效时间窗口工作；其代码已提供 720→736 的补边逻辑。直接输入 30 FPS 会破坏训练时的帧级时间尺度。
- 影响：事件时间以 `frame_index / 25.0` 映射回源视频秒数；代理仅用于推理且被 Git 忽略，最终叠加仍渲染在原始带音频视频上。

## D-009——最终冠军权重使用 33 帧长序列模型

- 日期：2026-09-01
- 状态：已接受；更正 D-008 中对时间窗口为 15 帧的初始描述
- 决策：使用 `ball_finetune_long_004` 的 7 个 fold 权重；其序列化参数为 33 帧、步长 2、25 FPS 输入，等效上下文约 2.56 秒。
- 理由：在 `chiron` 的 `ballspot-infer` 中实际加载官方 fold 0 权重，读取到 `num_frames=33` 和 `frame_stack_size=33`；这是比 README 对早期模型的概述更直接的运行证据。
- 影响：自定义适配器需要为每个有效预测帧准备中心两侧各 32 个推理帧的上下文。25 FPS CFR 代理、1280×720 原始尺寸和模型内部 1280×736 补边的决定不变。

## D-005——画外区间在主观审查中不可评价

- 日期：2026-08-31
- 状态：已接受
- 决策：使用 `VISIBLE`、`PARTIAL`、`OFFSCREEN`，画外动作不自动算作假阴性。
- 理由：滞后或静止的单机位可能没有拍到动作证据。
- 影响：报告必须区分输入可观测性和模型行为。

## D-006——初始 Conda 推理环境暂不编译 VPF

- 日期：2026-08-31
- 状态：已接受，步骤 03 重新评估
- 决策：`ballspot-infer` 安装上游 Python/PyTorch 依赖，但暂不编译 NVIDIA VideoProcessingFramework；初始自定义视频适配使用 FFmpeg/OpenCV 解码。
- 理由：上游通过定制 Docker 镜像提供 VPF，而当前项目明确使用 Conda；约 10 分钟 PoC 可以先采用 CPU 解码和 GPU 推理，降低环境准备风险。
- 影响：步骤 03 必须验证吞吐量和帧时间准确性；只有确有性能需求时才接入 VPF。
