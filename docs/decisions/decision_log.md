# 决策日志

记录影响架构、模型行为、数据结构或可复现性的决策。决策被推翻时不得删除原记录，应新增条目并注明替代关系。

## D-001——分离推理和可视化计算

- 日期：2026-08-31
- 状态：已接受
- 决策：GPU 模型推理在 `chiron` 执行；可视化渲染和审查在本地执行。
- 理由：远端拥有 8 张 RTX A6000，本地是目标审查环境。
- 影响：原始稠密分数和运行清单构成远端到本地的交接契约。

## D-002——使用 Conda 管理项目环境

- 日期：2026-08-31
- 状态：已接受
- 决策：分别使用 `ballspot-viz` 和 `ballspot-infer`，不向 `base` 安装项目依赖。
- 理由：可视化和旧模型依赖不同，两端都必须可复现。
- 影响：依赖确认后维护两个独立环境文件。

## D-004——初始模型路线采用标准 Pass/Drive 标签

- 日期：2026-08-31
- 状态：暂定，步骤 03 重新验证
- 决策：从预训练的 2023 SoccerNet Pass/Drive 方案开始，并保留标准 `Drive` 标签。
- 理由：两分类体系直接匹配当前 Ball Action Spotting 范围。
- 影响：不得把 `Drive` 静默解释为所有接球。正式 GT 需要明确事件时间定义。

## D-005——画外区间在主观审查中不可评价

- 日期：2026-08-31
- 状态：已接受
- 决策：使用 `VISIBLE`、`PARTIAL`、`OFFSCREEN`，画外动作不自动算作假阴性。
- 理由：滞后或静止的单机位可能没有拍到动作证据。
- 影响：报告必须区分输入可观测性和模型行为。

## D-006——初始 Conda 推理环境暂不编译 VPF

- 日期：2026-08-31
- 状态：已接受，步骤 03 重新评估
- 决策：`ballspot-infer` 安装上游 Python/PyTorch 依赖，但暂不编译 NVIDIA VideoProcessingFramework；初始自定义视频适配使用 FFmpeg/OpenCV 解码。
- 理由：上游通过定制 Docker 镜像提供 VPF，而当前项目明确使用 Conda；约 10 分钟 PoC 可以先采用 CPU 解码和 GPU 推理，降低环境准备风险。
- 影响：步骤 03 必须验证吞吐量和帧时间准确性；只有确有性能需求时才接入 VPF。
