# 测试策略

状态：生效中  
适用范围：基础设施、推理、后处理、可视化和 PoC 主观审查

## 1. 原则

- 测试必须产生可检查证据，不能只看退出码。
- 每次有意义的测试都追加到 `docs/testing/test_log.md`。
- 单元测试和结构测试在本地执行，必要时也在 `chiron` 执行。
- GPU 推理先测试 60～90 秒，再运行完整 10 分钟。
- 只有时间对齐和产物验证通过后才允许完整推理。
- 主观审查统计必须与基于 GT 的正式指标明确区分。

## 2. 基础设施测试

### T-INFRA-001 Git 同步

- 向 GitHub 推送一个已知提交，再在 `chiron` 拉取。
- 通过标准：本地和远端 `git rev-parse HEAD` 完全一致。

### T-INFRA-002 Conda 隔离

- 在两个命名环境中通过 `conda run` 执行 Python 和 FFmpeg。
- 通过标准：命令来自目标环境，项目包没有安装到 `base`。

### T-INFRA-003 远端 GPU

- 导入 PyTorch，报告版本、CUDA 和设备数，选择一张 A6000 执行小型张量运算。
- 通过标准：CUDA 可用、至少有一张 GPU、计算完成且没有驱动/运行时不匹配。

### T-INFRA-004 资产完整性

- 在两端计算源 MP4 的 SHA-256 和字节数。
- 通过标准：哈希和字节数完全一致。

## 3. 单元和契约测试

### T-UNIT-001 时间转换

- 测试秒数、帧号、源视频相对时间和 `HH:MM:SS.mmm` 显示时间的转换。
- 覆盖零点、小数帧边界、区间偏移和最后一帧。
- 通过标准：往返误差不超过一帧。

### T-UNIT-002 事件结构

- 验证必填字段、允许标签、置信度范围、时间排序、区间边界和唯一 ID。
- 通过标准：错误事件明确失败；有效 JSON 和 CSV 描述同一组事件。

### T-UNIT-003 时序峰值提取

- 测试孤立峰、平台峰、相邻同类事件、同时出现的不同类别和边界事件。
- 通过标准：按配置窗口去重，且不删除有效相邻事件。

### T-UNIT-004 可见性状态

- 验证 `VISIBLE`、`PARTIAL`、`OFFSCREEN` 区间的重叠、空洞和边界。
- 通过标准：每个被审查事件只对应一个可见性状态。

## 4. 模型适配测试

### T-MODEL-001 解码和预处理

- 解码包含日文路径的代表性短片。
- 验证帧顺序、形状、灰度转换、缩放策略和采样时间戳。

### T-MODEL-002 确定性冒烟推理

- 使用相同模型、配置和随机种子重复运行同一段 60～90 秒视频。
- 通过标准：时间戳和分数在规定数值容差内一致。

### T-MODEL-003 分数合理性

- 检查有限数值、预期维度、两个类别、区间覆盖和分数分布。
- 通过标准：没有 NaN/Inf、缺失时间块或无法解释的时间跳跃。

### T-MODEL-004 可视化时间对齐

- 将选定分数峰值与解码帧人工比对。
- 通过标准：无系统性偏移，误差在规定帧容差内。

## 5. 集成测试

### T-INT-001 远端到本地产物交接

- 在远端生成原始分数和清单，传回本地并验证校验和与结构。
- 通过标准：本地工具无需手工修改即可读取。

### T-INT-002 事件到叠加视频覆盖

- 渲染包含已知事件的短片。
- 通过标准：每个事件恰好显示一次，标签、置信度和源时间码正确。

### T-INT-003 只修改阈值重新渲染

- 在本地改变阈值或 NMS 配置，不重新运行模型。
- 通过标准：事件选择和叠加发生变化，原始分数哈希保持不变。

## 6. 视频渲染质检

### T-VIDEO-001 容器和编码

- 使用 FFprobe 检查输出并完整解码。
- 通过标准：H.264 MP4 或约定格式可播放且无解码错误。

### T-VIDEO-002 时长和帧率

- 比较源区间与输出时长及帧数。
- 通过标准：除非明确记录原因，否则时长差不超过一帧。

### T-VIDEO-003 音频同步

- 有音频时予以保留，并检查开头、中间和结尾。
- 通过标准：无可感知漂移，测量目标小于 100 ms。

### T-VIDEO-004 叠加可读性

- 检查普通、明亮、昏暗、拥挤和画面边缘场景。
- 通过标准：标签、置信度、时间码和可见性警告清晰，且不遮挡关键比赛内容。

## 7. PoC 主观审查

- 查看每个预测事件及其前后文。
- 连续观看完整区间，记录明显可见的漏检。
- 将每个预测标为正确、标签错误、时间误差、重复、误检、画外不可观测或歧义。
- 保存代表性成功案例和最有信息价值的失败案例。

建议的非正式继续/停止判断：高置信度且可见的预测大多合理；多数合理事件时间误差约为 1 秒以内；误检不持续成片出现；Pass 和 Drive 都有有意义的样例；能够明确区分摄像问题和模型问题。

## 8. 每次运行所需证据

- 日期、时间和执行者
- Git 提交
- 机器和 Conda 环境
- 命令或命令手册章节
- 输入路径、区间、大小和校验和
- 模型、权重和配置身份
- 退出码和结果摘要
- 产物路径和校验和
- 通过/失败结论和后续动作
